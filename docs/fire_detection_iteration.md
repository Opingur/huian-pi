# 小火苗检测优化记录

本记录保留真实测试中发现的问题和对应工程调整，不包含未经测量的准确率或召回率结论。

## V1：整帧早期方案

- 方案：仅对完整监控画面运行 `models/fire_n.pt`。
- 现象：慢速电气小火苗在整幅画面中占比较小，存在漏检。
- 问题：小目标在整帧缩放后的有效像素不足，单次结果容易波动。

## V2：2×2 重叠分块

- 方案：保留整帧推理，同时使用 2×2 重叠分块；将 tile 检测框映射回原图后进行 NMS 合并。
- 现象：已经能够检出小火苗，但 raw fire 结果仍有交替，展示状态可能因短时漏检而回落。
- 问题：检测框保持和告警状态保持共用同一时长，无法同时满足“框真实”和“告警稳定”。

## V3：状态链修正

- 方案：加入连续推理确认、`FIRE CANDIDATE` / `FIRE` / `FIRE HOLD` 标签，并使候选框能够提升综合状态。
- 现象：真实候选框不会再对应绿色“正常运行”。
- 问题：仍需将 bbox 保持和视觉告警保持分离，以避免框消失后状态过早回绿。

## Final：小目标增强与双保持状态

- 方案：3×3 重叠分块、完整画面保留、坐标映射、NMS 合并、连续 2/5 次确认。
- 参数：`imgsz=640`、`confidence=0.15`、`tile_overlap=0.20`、`nms_iou_threshold=0.45`、`bbox_hold_seconds=3.0`、`visual_alert_hold_seconds=6.0`。
- 改进：最近真实检测框最多保持 3 秒并标记 `FIRE HOLD`；最近视觉火焰证据最多保持 6 秒，期间界面显示“持续观察”，但不生成新框。
- 限制：未重新训练或更换 `fire_n.pt`；最终效果仍需在 Raspberry Pi 5 的真实演示视频上复测，不对准确率作未经测量的声明。

## 答辩表述

针对小火苗在整幅监控画面中占比较小、容易漏检的问题，系统优化了火焰检测推理流程：使用重叠分块放大局部目标、将检测结果映射回原图并合并重复框，再通过连续帧确认和状态滞回提高预警稳定性。旧版本输出保留为工程迭代证据。
